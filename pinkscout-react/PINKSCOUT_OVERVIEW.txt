1. PROJECT OVERVIEW
--------------------------------------------------------------------------------

PinkScout is a comprehensive web-based scouting application designed for FRC
(FIRST Robotics Competition) teams. The application enables teams to collect,
analyze, and leverage match data during competitions to make strategic decisions
about alliance partnerships.

Live URL: https://pinkscout.net (deployed on Vercel)

Primary Use Cases:
1. During Competitions: Scouts sit in the stands and record what each robot
   does during matches using the Scouting Form
2. Between Matches: Team strategists analyze the collected data to identify
   strong/weak teams
3. Alliance Selection: During alliance selection, teams use the Recommended
   Alliance feature to identify optimal partners
4. Post-Competition: Teams review their own performance using the Analytics page

4. DATABASE SCHEMA (Supabase/PostgreSQL)
================================================================================

TABLE: profiles - User accounts
--------------------------------------------------------------------------------
id UUID PRIMARY KEY          -- Matches Supabase auth.users(id)
email TEXT NOT NULL          -- User's email address
display_name TEXT            -- Shown on scouting entries
role TEXT                    -- 'scout', 'scoutLead', 'masterAdmin'
team_number INTEGER          -- User's FRC team (e.g., 1551)
scouting_id TEXT             -- Legacy team isolation identifier
is_team_lead BOOLEAN         -- TRUE = can generate team codes
team_lead_uid UUID           -- Points to Team Lead's profile (for members)
team_code TEXT               -- The code used to join team
created_at TIMESTAMPTZ
updated_at TIMESTAMPTZ


TABLE: team_codes - Team invite codes
--------------------------------------------------------------------------------
code TEXT PRIMARY KEY        -- 6-character code like "92WCJK"
team_lead_uid UUID NOT NULL  -- Who created this code
team_lead_email TEXT         -- For display purposes
active BOOLEAN               -- FALSE = code is invalidated
created_at TIMESTAMPTZ
deactivated_at TIMESTAMPTZ   -- When code was invalidated


TABLE: scouting - Match scouting entries (core data)
--------------------------------------------------------------------------------
id UUID PRIMARY KEY

-- Match identification
team_number INTEGER NOT NULL -- Team being scouted (not the scouter's team)
match_number INTEGER NOT NULL-- Qualification match number
event_key TEXT NOT NULL      -- TBA event key like "2026miket"
event_year INTEGER           -- Year extracted from event_key
alliance_color TEXT          -- 'red' or 'blue'

-- Ownership & isolation
scouter_uid UUID NOT NULL    -- Who submitted this entry
scouter_name TEXT            -- Display name at submission time
team_lead_uid UUID           -- For filtering by team
scouting_id TEXT             -- Legacy isolation

-- Match Info
starting_position TEXT       -- 'left', 'center', 'right' on field

-- Auto Period (20 seconds - autonomous)
auto_fuel_scored INTEGER     -- Balls scored in Hub
auto_shots_attempted INTEGER -- Total shots taken (for accuracy calc)
auto_cycles_completed INTEGER-- Full cycles completed
auto_tower_climb TEXT        -- 'none' or 'level1' (10pts, max 2 robots)

-- Teleop Period (2:20 - driver controlled)
teleop_fuel_active INTEGER   -- Balls scored when Hub is active (1pt each)
teleop_fuel_inactive INTEGER -- Balls scored when Hub inactive (0pts)
teleop_balls_cycled INTEGER  -- Balls moved to alliance side

-- Endgame (final 30 seconds)
endgame_tower_level TEXT     -- 'none', 'level1'(15pts), 'level2'(20pts), 'level3'(30pts)
endgame_fuel_scored INTEGER  -- Balls during endgame (all Hubs active)

-- Performance assessment
hub_control_first BOOLEAN    -- Did this alliance win auto period?
robot_role TEXT              -- 'shooter', 'cycler', 'defense'
notes TEXT                   -- Free-text observations
created_at TIMESTAMPTZ


TABLE: epa_baseline - Cached Statbotics EPA data
--------------------------------------------------------------------------------
id TEXT PRIMARY KEY          -- Format: "teamNumber_year" (e.g., "254_2026")
team_number INTEGER
year INTEGER
epa_total NUMERIC            -- Overall EPA score
epa_auto NUMERIC             -- Auto period contribution
epa_teleop NUMERIC           -- Teleop contribution
epa_endgame NUMERIC          -- Endgame contribution
source TEXT                  -- Always 'statbotics'
raw_data JSONB               -- Full API response preserved
imported_at TIMESTAMPTZ


TABLE: adjusted_epa - Calculated EPA (scouting + Statbotics blend)
--------------------------------------------------------------------------------
id TEXT PRIMARY KEY          -- Format: "teamNumber_eventKey"
team_number INTEGER
event_key TEXT
baseline_epa JSONB           -- Original Statbotics values
adjustment JSONB             -- Delta from scouting data
adjusted_epa JSONB           -- Final blended values
scouting_entries_count INTEGER
calculated_at TIMESTAMPTZ

5. AUTHENTICATION SYSTEM
================================================================================

How Login Works:
1. User enters email/password on Login page
2. Supabase Auth validates credentials
3. On success, AuthContext fetches user's profile from profiles table
4. AuthContext calculates roleContext with all permissions
5. User is redirected to Home page

AuthContext.jsx - Global Auth State:
--------------------------------------------------------------------------------
const AuthContextValue = {
  // Current user data
  user,                          // Supabase auth user object
  userProfile,                   // Profile from database
  isAdmin,                       // Has admin access?
  roleContext,                   // Full permission object
  loading,                       // Is auth state being checked?

  // Auth actions
  login(email, password),        // Sign in
  signup(email, password, username, signupCode, teamNumber, isTeamLead),
  logout(),                      // Sign out
  updateUserProfile(updates),    // Update profile fields
  refreshRoleContext()           // Reload permissions
};

Role Context Object (RBAC):
--------------------------------------------------------------------------------
roleContext = {
  role: 'scout' | 'scoutLead' | 'masterAdmin',
  userUid: 'uuid-string',        // User's Supabase ID
  isMasterAdmin: boolean,        // rtmbe20@gmail.com = true always
  canViewAll: boolean,           // Can see all team's data?
  isTeamLead: boolean,           // Can manage team members?
  teamLeadUid: 'uuid-string',    // Used for scouting data isolation
  scoutingId: 'string',          // Legacy isolation field
  teamCode: 'ABCD12'             // Current team invite code
}

6. TEAM SYSTEM (Team Codes & Member Management)
================================================================================

Purpose:
The team system allows groups of scouts to share scouting data. A Team Lead
creates an invite code, and members join using that code. All scouting entries
are tagged with the Team Lead's UID, enabling data filtering.

CREATING A TEAM (Becoming a Team Lead):
--------------------------------------------------------------------------------
User Flow:
1. Go to Profile page (/profile)
2. Check the "Team Lead Account" checkbox
3. System generates a unique 6-character code (A-Z excluding I,O + 2-9)
4. Code is displayed on Profile page with a "Copy" button
5. Share this code with team members

Backend Process (teamCodeService.js):
async function generateTeamCode(teamLeadUid, teamLeadEmail) {
  // 1. Check if user already has an active code
  const existingCode = await getTeamLeadCode(teamLeadUid);
  if (existingCode) {
    // Update profile to ensure is_team_lead = true
    await supabase.from('profiles').update({
      is_team_lead: true,
      team_code: existingCode
    });
    return existingCode;
  }

  // 2. Generate unique 6-char code with collision checking
  let code;
  do {
    code = generateRandomCode(); // From "ABCDEFGHJKLMNPQRSTUVWXYZ23456789"
    const exists = await checkCodeExists(code);
  } while (exists);

  // 3. Save to team_codes table
  await supabase.from('team_codes').insert({
    code, team_lead_uid, team_lead_email, active: true
  });

  // 4. Update user's profile
  await supabase.from('profiles').update({
    is_team_lead: true,
    team_code: code
  });

  return code;
}


JOINING A TEAM (Member Flow):
--------------------------------------------------------------------------------
User Flow:
1. During signup OR on Profile page, enter a team code
2. System validates the code is active
3. User's profile is linked to the Team Lead
4. User can now see all scouting data submitted by their team

Backend Process:
async function linkMemberToTeam(memberUid, teamLeadUid, teamCode) {
  await supabase.from('profiles').update({
    team_lead_uid: teamLeadUid,    // Link to Team Lead
    team_code: teamCode,            // Store which code was used
    is_team_lead: false             // Member, not lead
  }).eq('id', memberUid);
}


TEAM MANAGEMENT (Profile Page):
--------------------------------------------------------------------------------
What Team Leads See:
- Large display of their team code (e.g., "92WCJK" in monospace font)
- "Regenerate Code" button (invalidates old code, creates new one)
- Team stats: # of members, # of total scouting entries
- List of team members with their names and emails
- Each member shows as "Member" badge


DATA ISOLATION:
--------------------------------------------------------------------------------
When scouting data is saved, it includes team_lead_uid:
const dataToSave = {

When data is retrieved, it filters by team_lead_uid:

Prerequisite: User must set their FRC team number in Profile

STEP 1: Categorize all teams by role (shooter/cycler/defense)
STEP 2: Calculate synergy score for each possible 3-team alliance
STEP 3: Return top 2 recommended alliances

Synergy Score Formula:
- 75% Performance (scoring average + cycles + climb rate)
- 15% Auto Rating (autonomous performance quality)
- 10% Ranking Points (official standings normalization)
- Diversity bonus for different roles (+20 for all different)

8. EPA CALCULATION SYSTEM (epaCalculationService.js - 624 lines)
================================================================================

Purpose: Blend official Statbotics EPA ratings with local scouting data to
produce more accurate team evaluations.

What is EPA?
EPA (Expected Points Added) is a metric from Statbotics that estimates how
many points a team contributes to their alliance's score. PinkScout imports
this baseline and adjusts it based on local observations.

Data Flow:
1. Statbotics API -> EPA Baseline -> epa_baseline table
2. Scouting Form -> Scouting Entries -> scouting table
3. EPA Service -> Analyzes scouting -> Calculates adjustment
4. Blended Result -> adjusted_epa table

Weight Progression (more scouting = more weight to scouting data):
--------------------------------------------------------------------------------
Scouted Matches | Scouting Weight | Statbotics Weight
----------------|-----------------|-------------------
0               | 0%              | 100%
1-3             | 10-30%          | 70-90%
4-8             | 30-60%          | 40-70%
9-12            | 60-90%          | 10-40%
13-15           | 90-99%          | 1-10%
16+             | 100%            | 0%

Adjustment Calculation Logic:
function calculateEPAAdjustment(scoutingMetrics, baseline) {
  // Calculate expected points from scouting
  const scoutedAutoPoints = avgAutoFuel + avgAutoClimb;
  const scoutedTeleopPoints = avgTeleopFuel + (avgCycles * 2);
  const scoutedEndgamePoints = avgEndgameClimb;
  const scoutedTotal = scoutedAutoPoints + scoutedTeleopPoints + scoutedEndgamePoints;

  // Delta from baseline
  const rawAdjustment = scoutedTotal - baseline.epaTotal;

  // Apply weight based on match count
  const weight = calculateScoutingWeight(matchCount);
  const consistencyMultiplier = 0.8 + (0.4 * consistency); // 0.8x to 1.2x

  return rawAdjustment * weight * consistencyMultiplier;
}

10. FRC 2026 REBUILT GAME DETAILS
================================================================================

Match Structure:
--------------------------------------------------------------------------------
Period    | Duration     | Description
----------|--------------|------------------------------------------
Auto      | 20 seconds   | Robots run pre-programmed routines
Teleop    | 2 min 20 sec | Drivers control robots, Alliance Shifts
Endgame   | 30 seconds   | All Hubs active, Tower climbing

Field Elements:
- Hubs: Goals where robots score Fuel (balls). Two per alliance.
- Alliance Shift: Alternates which Hub is "active" during Teleop
- Tower: Climbing structure with multiple levels for endgame points

Scoring Table:
--------------------------------------------------------------------------------
Action                  | Points | Notes
------------------------|--------|--------------------------------
Fuel in Active Hub      | 1 pt   | Only active Hub counts in Teleop
Fuel in Inactive Hub    | 0 pts  | Tracked for strategy
Auto Tower Climb L1     | 10 pts | Max 2 robots, Level 1 only
Endgame Tower L1        | 15 pts | Off the carpet
Endgame Tower L2        | 20 pts | Above low rung
Endgame Tower L3        | 30 pts | Above mid rung

Auto Bonus:
The alliance that scores more fuel in auto gets to choose which opposing
Hub becomes inactive first during Teleop.

Robot Roles (User-defined in scouting):
- Shooter: Focuses on scoring fuel into Hubs
- Cycler: Moves balls from opponent's side to alliance's side
- Defense: Blocks opponents from scoring, plays physical defense

--------------------------------------------------------------------------------

setFormData(prev => ({
  ...prev,
  fieldName: newValue
}));

// Updating array state
setItems(prev => [...prev, newItem]);        // Add

Protected Route Pattern:
--------------------------------------------------------------------------------
function ProtectedRoute({ children }) {
  const { user, loading } = useAuth();

  if (loading) return <LoadingSpinner />;
  if (!user) return <Navigate to="/login" replace />;

  return children;
}
